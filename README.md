# Community Loan App

Node.js + Express + SQLite back-end, with a mobile-first front-end (`public/index.html`) styled after your sample.

## Run locally
```bash
npm install
export JWT_SECRET=$(openssl rand -hex 32)
export ADMIN_TOKEN=choose-a-long-random-string
export DATA_KEY=$(openssl rand -hex 32)   # encrypts ID and bank numbers. Back it up: losing it loses that data.
export LENDER_NAME="Your Lender Inc." SEC_NO="CA No. ..." RATE=0.3
npm start
```
App: http://localhost:3000  ·  Admin: http://localhost:3000/admin.html (enter ADMIN_TOKEN)

## Admin back office
Open `/admin.html` and log in with `ADMIN_TOKEN`. It covers:
- **All Members** — search/filter by date, see each member's wallet balance, level and status, and correct their data: Checking data (full profile — ID, address, emergency contacts, signature, bank info, with photo delete), Wallet (a logged, auditable balance correction — not an overwrite of the real disbursed-loan ledger), Withdrawal Code (admin-only, never customer-set), Level (correct it by hand when the computed value is wrong; clear the override to go back to automatic — see below), ID Identity, Password (reset), Bank Card Number, and Enable/Disable (a disabled account can't log in).
- **Borrowing List** — Review (approve/reject/disburse/mark completed), Modify Loan (correct amount/term, recomputes the total), View Contract, and Delete, plus the same member-correction shortcuts as the Members table.
- **Withdrawal List** — mark a request paid or reject it.
- **Notifications** — send a one-off message to a member (autocomplete by phone) or broadcast to everyone, and see a combined history of every automatic and admin-sent message. There's deliberately no credit-score tool.

## Before real users
1. Put your customer's real legal name, SEC number and interest rate in the env vars / `config.js`. `RATE` is a percent per **month**, flat (currently 0.3, matching ₱80,000 / 6 months → ₱13,573 per installment). `MIN_AMOUNT`, `MAX_AMOUNT` and `TERMS` control the loan slider and term buttons.
2. **Withdrawal code.** Set only by staff, from the admin page (Members → Withdrawal Code, or Borrowing List). The member is notified of the code through their in-app notification bell — it's never typed in or generated by the customer. Only a bcrypt hash is stored (`users.pin_hash`); withdrawals are checked against it server-side.
3. **Level (1–5).** Shown on the Account page instead of a credit score. It's computed automatically from real activity, and a user can never buy or unlock a higher one:
   - 1: registered
   - 2: profile complete (ID, personal info, bank account, signature)
   - 3: has applied for a loan
   - 4: has an approved, disbursed, or completed loan
   - 5: has fully repaid a loan (admin marks an application "completed" once it's paid off)

   Staff can still correct it by hand from Members → Level, for the rare case the computed value is wrong (a migrated account, a data-entry fix). That override simply replaces the computed value until it's cleared — clearing it (the "back to automatic" link in the same modal) returns the member to whatever the real activity above computes.
4. Have a lawyer write the contract text (marked `[Lender legal name]` / `[SEC registration no.]` in `public/index.html`, `config.js`, and the admin contract viewer) and the Privacy Notice.
5. Deploy behind HTTPS only (Render, Railway, a VPS with Caddy/nginx). Keep `uploads/` and `loan.db` off public paths and back them up.
6. Check Data Privacy Act obligations (NPC registration if applicable) and the SEC rules for lending/financing companies.
7. Add SMS OTP verification and self-service password reset (the admin page can already reset a password for someone) as next steps.
